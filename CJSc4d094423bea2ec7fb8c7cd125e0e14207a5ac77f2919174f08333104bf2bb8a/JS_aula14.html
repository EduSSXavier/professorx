book_2 Introdução às APIs

Introdução às APIs

book_2 O que é uma API?

API significa Application Programming Interface (Interface de Programação de Aplicações). É uma forma de diferentes sistemas se comunicarem entre si através de regras bem definidas.

APIs são usadas para permitir que aplicações acessem funcionalidades ou dados de outras aplicações, serviços ou plataformas.

Em resumo, uma API permite que diferentes sistemas se comuniquem e compartilhem dados de maneira padronizada.

Imagine que você está em um restaurante:

  • Você: Aplicação cliente (navegador, app)
  • Cozinha: Servidor com os dados
  • Garçom: API

Você não vai até a cozinha pegar sua comida. O garçom (API) leva seu pedido, solicita o que você precisa na cozinha e traz para você. A API funciona da mesma forma: ela recebe seu pedido de dados, processa os dados, busca no servidor e retorna para sua aplicação.


Componente No Restaurante / Na Programação
Você (o Cliente) O software que precisa de dados (seu código JavaScript).
O Garçom (a API) O intermediário que recebe seu pedido e o leva à cozinha.
A Cozinha (o Servidor) O software que possui os dados e a lógica de negócio.
O Pedido (a Requisição) A solicitação que seu código envia para a API (ex: "Quero os dados do clima de São Paulo").
O Prato (a Resposta) Os dados que a API retorna para o seu código (ex: um arquivo JSON com a temperatura e umidade).

book_2 E para que servem?

APIs servem para expor funcionalidades e dados de forma segura e controlada. Elas permitem que desenvolvedores usem serviços complexos (como mapas, pagamentos ou dados de redes sociais) sem precisar entender ou acessar o código-fonte desses serviços.

book_2 Por que usar APIs?

  • Reutilização de dados Você não precisa ter todos os dados, mas pode reutilizar partes desses dados que para requisitar dados de outros serviços
  • Flexibilidade As APIs podem ser personalizadas para atender aos requisitos da sua aplicação
  • Segurança e privacidade As APIs podem fornecer recursos de segurança e privacidade, como autenticação e autorização
  • Integração facilitada As APIs permitem que diferentes sistemas e aplicações se comuniquem facilmente
  • Especialização: Cada serviço faz o que faz de melhor (previsão do tempo, mapas, dados financeiros)
  • Atualização em tempo real: Os dados vêm diretamente direto da fonte
  • Economia de recursos: Não precisa armazenar tudo localmente

book_2 Exemplos práticos:

  • Previsão do tempo: Aplicativos consultam APIs meteorológicas
  • Login com Google/Facebook: Usar APIs de autenticação
  • Mapas: Google Maps API
  • Pagamentos: APIs de bancos e cartões (PayPal, Stripe)

fetch()

book_2 O que é fetch()?

No JavaScript moderno, a maneira mais comum e recomendada de fazer requisições de rede é usando a função fetch().

O fetch() é uma função nativa do navegador que fornece uma interface para realizar requisições HTTP.

Elas podem ser usadas para enviar requisições HTTP (como o seu "pedido" no restaurante) e processar as respostas.

book_2 Por que usar fetch()?

  • Simples e Direto: A sintaxe do fetch() é fácil de entender e usar.
  • Baseado em Promises: Isso facilita o tratamento de operações assíncronas.
  • Flexível: Permite configurar requisições HTTP de várias maneiras (métodos, cabeçalhos, corpo, etc.).
  • Suporte Nativo: Não requer bibliotecas externas, funciona diretamente no navegador.

book_2 Sintaxe Básica

A sintaxe básica para uma requisição é:

fetch(url)
    .then(response => { 
        // Processa a resposta
    })
    .catch(error => {
        // Trata erros de rede
    });


Além disso, o fetch() oferece várias vantagens importantes:

  • Suporte a Diferentes Tipos de Resposta: Pode lidar com respostas em vários formatos, como JSON, texto, blobs, etc.
  • Controle Avançado: Permite configurar detalhes da requisição, como métodos HTTP, cabeçalhos, corpo da requisição, entre outros.
  • Integração com APIs Modernas: Funciona bem com outras APIs modernas do JavaScript, como Service Workers e WebSockets.

Exemplo de uso do fetch() para obter dados de uma API:

const cep = '01001000'; // Exemplo de CEP
const url = `https://viacep.com.br/ws/${cep}/json/`;

fetch(url)
  .then(response => {
    if (!response.ok) {
      throw new Error('Erro na requisição: ' + response.status);
    }
    return response.json();
  })
  .then(data => {
    console.log(data);
    // Exemplo: Acessar o nome da rua e a cidade
    console.log('Logradouro:', data.logradouro);
    console.log('Localidade:', data.localidade);
  })
  .catch(error => {
    console.error('Erro ao buscar CEP:', error);
  });

Esse exemplo faz uma requisição para a API ViaCEP, que retorna informações sobre um CEP específico. O código trata erros de rede e exibe os dados retornados no console.

Requisições

book_2 Requisições GET

GET é o método HTTP mais comum. Ele busca (obtém) dados de um servidor sem modificá-los.

O método GET é o tipo de requisição mais comum e é usado geralmente para solicitar dados de um recurso específico. Ele é o equivalente a "pedir o cardápio" ou "pedir o prato" sem alterar nada na cozinha.

Ao usar fetch() , o método GET é o padrão, então você não precisa especificá-lo. Basta passar a URL do recurso que você deseja acessar.



book_2 Exemplo Básico de Requisição GET:

fetch('https://api.exemplo.com/dados')
  .then(response => response.json())
  .then(data => {
    console.log(data);
  })
  .catch(error => {
    console.error('Erro:', error);
  });

Promises e Tratamento de Erros

book_2 O que são Promises?

A chave para entender o fetch() é o conceito de Promise (Promessa). Uma Promise é um objeto que representa a eventual conclusão (ou falha) de uma operação assíncrona.



Em outras palavras, uma Promise representa um resultado futuro que pode ser resolvido ou rejeitado.



Uma Promise pode estar em um de três estados:

  • Pending (Pendente): O estado inicial; a operação ainda não foi concluída.
  • Fulfilled (Realizada): A operação foi concluída com sucesso.
  • Rejected (Rejeitada): A operação falhou.


book_2 Lidando com Promises

O Fluxo de uma Requisição é o seguinte:

  1. fetch(url) : Inicia a requisição e retorna uma Promise.
  2. .then(response => response.json()) : O primeiro .then recebe o objeto Response e o transforma em uma nova Promise que resolve com os dados em formato JSON.
  3. .then(data => ...) : O segundo .then recebe os dados em formato JSON prontos para uso.
  4. .catch(error => ...) : Captura qualquer erro de rede que tenha ocorrido durante o processo.


book_2 Tratamento de Erros

O tratamento de erros é crucial para criar aplicações robustas. Ao trabalhar com APIs e fetch() , é vital entender a diferença entre:

  • Erro de Rede: Capturado pelo .catch(), ocorre quando a requisição não consegue ser enviada ou o servidor não responde (ex: sem internet, URL malformada, falha de DNS). Neste caso, a Promise é rejeitada e o .catch() é acionado.
  • Erro de Resposta HTTP: Ocorre quando a requisição é enviada e o servidor responde, mas com um código de status que indica falha (ex: 404 Not Found , 500 Internal Server Error , 401 Unauthorized ). Neste caso, a Promise é realizada (sucesso), e o .catch() NÃO é acionado. Para tratar erros HTTP, você deve verificar a propriedade response.ok ou response.status manualmente

Criação de API com Python e Flask

book_2 Importante:

Apesar do foco desta aula ser o consumo de uma API já pronta para uso, faremos aqui uma breve demosntração de como criar uma API simples usando Python e Flask, para que você entenda o funcionamento básico de uma API.


É importante lembrar que o uso destas tecnologias não é a única maneira de criar APIs (há outras aternativas igualmente boas, como Django, Express.js, Node.js e mais).


A opção do autor deste curso pelo Flask é motivada simplesmente pela sua preferência pessoal, principalmente pela sua leveza, simplicidade e facilidade de uso.

exercise Criando sua própria API

Agora vamos criar uma API simples do zero usando Python e Flask!



Passo 1: Instalar o Flask

pip install flask flask-cors


Passo 2: Criar o arquivo da API

Crie um arquivo chamado api.py e adicione o seguinte código:

from flask import Flask, jsonify, request
from flask_cors import CORS

app = Flask(__name__)

CORS(app) # Permite requisições de outros domínios

# Dados de exemplo (banco de dados simulado)
livros = [
    {"id": 1, "titulo": "1984", "autor": "George Orwell", "ano": 1949},
    {"id": 2, "titulo": "Dom Casmurro", "autor": "Machado de Assis", "ano": 1899},
    {"id": 3, "titulo": "O Hobbit", "autor": "J.R.R. Tolkien", "ano": 1937},
    {"id": 4, "titulo": "Cem Anos de Solidão", "autor": "Gabriel García Márquez", "ano": 1967},
]

# Rotas 
@app.route('/')
def home():
    return jsonify({
        "mensagem": "Bem-vindo à API de Livros!",
        "rotas": {
            "/livros": "Lista todos os livros",
            "/livros/<id>": "Busca um livro por ID"
            }
        })

# GET - Listar todos os livros
@app.route('/livros', methods=['GET'])
def listar_livros():
    return jsonify(livros)

# GET - Buscar livro por ID
@app.route('/livros/<int:id>', methods=['GET'])
def buscar_livro(id):
    livro = next((l for l in livros if l['id'] == id), None)
    if livro:
        return jsonify(livro)
    else:
        return jsonify({"erro": "Livro não encontrado"}), 404

# Iniciar o servidor
print("API rodando na porta 5000")
app.run(port=5000)


Passo 3: Executar a API

python api.py


Agora crie um frontend usando HTML, CSS e JavaScript para consumir essa API
